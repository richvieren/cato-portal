# shared/chart-demo — DEMO CHART ASSETS ONLY

Everything in this folder exists to show the delivered product on the landing page.
It is the only folder that carries chart-render code or chart data.

## Hard rules

1. **Never a client's chart.** The `natal_charts` table holds 151 client rows. None of them
   may be rendered, screenshotted, or copied here. Client birth data is personal data.
2. **The demo chart is currently SYNTHETIC.** Invented birth data, generated 2026-09-16, belongs
   to nobody. `config/brand.json` → `demo_chart.consent` reads `NOT_REQUIRED_SYNTHETIC`, and the
   page labels it as a sample. If Cato approves her own chart, swap `demo-chart.json`, re-run the
   capture, and set `consent` to `OBTAINED`. Nothing else changes.

   The sample chart, for reference (all invented):
   14 March 1989, 09:42, Lisbon. Gemini Rising 12°24′, Pisces Sun in the 10th, Scorpio Moon in the
   6th, chart ruler Mercury in Pisces in the 10th, MC Pisces. Water 3 / air 2 / fire 1 / earth 1,
   mutable 3. Whole-sign houses derived from the Ascendant, aspects computed from the longitudes,
   element and modality counts derived from the placements, so every section resolves real snippet
   text rather than placeholder copy.
3. **This is a snapshot, not a live import.** Do not fetch these files from the portal at
   runtime and do not symlink across repos. Copy them in, record the commit below, refresh
   deliberately.

## Capture settings (2026-09-16 re-render)

The ten assets the admired page uses were re-rendered at `--force-device-scale-factor=2`,
so a plate shown 550-650 CSS px wide is still sharp on a retina screen. Composition is
unchanged: each was captured at the same 760px harness viewport as the original run, and
every trimmed file came out within 1% of exactly 2x its predecessor.

`*.mobile.png` are separate captures at a 430px viewport. Reason: a desktop screenshot of
the product scaled down to a 390px phone makes the product's own body text unreadable, which
defeats the purpose of a proof image. At 430px the portal reflows and the text stays at
phone size.

Four sections do NOT reflow at that width — `w-big3`, `profile-hero`, `section-biz` and
`section-planets` keep their cards side by side and overflow the viewport, so their phone
captures came out clipped. Those four have no `.mobile.png`, and the build falls back to the
desktop plate for them. Do not regenerate them at 430px without checking the crop.

`build.mjs` picks a `.mobile.png` up automatically when the file exists, and emits nothing
extra when it does not.


## LIVE RENDER (2026-09-16) — the page no longer uses screenshots

The landing page renders the product live in the browser from these files. The
captured PNGs are retained for reference but the page does not load them.

- `boot-live.js` runs the same 20 render calls the portal's profile page runs.
- `snippets-subset.json` is 9,395 bytes: exactly the entries this chart
  resolves, against a 202,080-byte full snippet file (4.4%). Generated by the
  same `findSnippet` lookups, which is copied verbatim from the portal's
  `profile.js` into `boot-live.js`. `profile.js` is NOT one of the three pinned
  files, so nothing pinned was patched.
- `../product-widgets.css` styles the ~45 class names the widgets emit. The
  widgets read exactly two portal tokens, `--stone` and `--mist`, both
  redefined there. Twelve colour literals are emitted inline by `widgets.js`
  and are overridden with `!important`, each marked in that file.

**A widget renders once into an offscreen staging node that owns its canonical
id, then the result is copied into every `[data-live="<id>"]` slot.** That is
how `w-big3` can appear both in the hero strip and at reason 4 without
duplicate ids.

If the pinned files are refreshed, re-check: the class list, the two tokens,
and the twelve inline literals.

## Refresh procedure

1. `git -C <portal> log --oneline -1` — record the new commit.
2. Copy the three JS files and re-render the PNGs from the same commit.
3. Update the table and the pinned commit above in the same change.
4. Re-run `node build.mjs`.
